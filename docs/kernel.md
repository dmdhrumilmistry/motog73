# Building the kernel from source

Motorola publishes the kernel for every g73 release. Build
`U1TNS34.82-12-7-26` matches tag `MMI-U1TNS34.82-12-7-26` in
[MotorolaMobilityLLC/kernel-mtk](https://github.com/MotorolaMobilityLLC/kernel-mtk).

## Quick build

```sh
kernel/fetch-clang.sh                             # AOSP clang r416183b (LLVM 12)
kernel/build-kernel.sh -c src/clang-r416183b      # stock config
kernel/build-kernel.sh -c src/clang-r416183b -g   # + G73 Open fragment
kernel/build-kernel.sh -c src/clang-r416183b -p   # + postmarketOS fragment
```

Output goes to `out/kernel/dist/`: `Image.gz`, `mt6855.dtb`, `modules/`,
`config` and `kernel.release`.

The script reproduces MediaTek's config logic (`scripts/gen_build_config.py`):

```
gki_defconfig
 + arch/arm64/configs/mgk_64_k510_defconfig
 + ext_config/moto-mgk_64_k510.config
 + ext_config/moto-mgk_64_k510-devonf.config
 [+ debug-*.config, kernel/configs/userdebug.config]   # -v userdebug
 [+ your fragments]                                     # -f / -g / -p
```

Options: `-k` writes the config only, `-f file` merges your own fragment,
`-v userdebug` adds Motorola's debug fragments.

**Compiler:** the tree is written for AOSP clang 12. Newer clang releases
report extra warnings in MediaTek's drivers, and both GKI's `CONFIG_WERROR=y`
and several MediaTek driver Makefiles turn them into errors. A clang 18 build
of this tag (`make -k`) fails on six warnings: `implicit-int`,
`unused-but-set-variable`, `strict-prototypes`, `deprecated-non-prototype`,
`single-bit-bitfield-constant-conversion` and `bitwise-instead-of-logical`.

Use `fetch-clang.sh` (recommended), or pass `-W` to build with a newer host
clang. `-W` merges [`configs/no-werror.config`](../kernel/configs/no-werror.config)
and adds `-Wno-error=<warning>` for those six. It only changes compiler
flags, not the KMI.

**Memory:** the stock config uses full LTO. Linking `vmlinux` needs about
16 GB of RAM. On smaller machines pass `-L` to use ThinLTO
([`configs/thinlto.config`](../kernel/configs/thinlto.config)), which links
in parallel with much less memory. LTO mode does not change the module ABI,
and CFI stays on. The GitHub Actions builds use `-L`, because a free runner
has only 16 GB.

## Full source tree (with out-of-tree modules)

Wi-Fi, Bluetooth, GPS, GPU, touch and other Motorola drivers live in separate
repositories that carry the same tag. Sync them all with `repo`:

```sh
mkdir devonf-kernel && cd devonf-kernel
repo init -u https://github.com/dmdhrumilmistry/motog73 -b main \
     -m kernel/manifests/devonf-U1TNS34.82-12-7-26.xml
repo sync -c -j"$(nproc)"
```

Each module has its own Kbuild under `vendor/mediatek/kernel_modules/` and
`motorola/kernel/modules/`. Build them against your kernel output with
`make -C kernel-5.10 O=<out> M=<module dir> ...`.

## Prebuilt kernel (from CI)

Once a release exists (none yet, and untested on hardware), download
`devonf-kernel-Image.gz`, `devonf-kernel-mt6855.dtb`,
`devonf-kernel-modules.tar.xz` and `devonf-kernel.release` from the
[Releases page](https://github.com/dmdhrumilmistry/motog73/releases) and
verify them with `sha256sum -c SHA256SUMS`. The `Image.gz` goes into your own
stock `boot.img`; try it with `fastboot boot` before flashing anything:

```sh
scripts/repack-boot.sh -s stock/devonf/images/boot.img \
    -k devonf-kernel-Image.gz -o boot-ci.img
fastboot boot boot-ci.img
```

The modules tarball and DTB are for reference and for the TWRP and
postmarketOS builds; see the warning on KMI compatibility below.

## Using a custom kernel on Android

Because of GKI, the stock `vendor_boot` and `vendor_dlkm` modules only load if
the kernel keeps the same KMI. Keep config changes small. The `g73open.config`
fragment only changes `LOCALVERSION`. To test a kernel:

```sh
# Put your Image.gz into the stock boot.img (keeps header v4, OS version, patch level)
scripts/repack-boot.sh -s stock/devonf/images/boot.img \
    -k out/kernel/dist/Image.gz -o out/kernel/boot-custom.img

fastboot boot out/kernel/boot-custom.img      # one-time test boot, if your bootloader allows it
scripts/flash.sh kernel out/kernel/boot-custom.img
```

The DTB/DTBO for the board overlay are generated by MediaTek's proprietary
DCT tool during Motorola's build, so keep using the stock `dtbo.img`.
